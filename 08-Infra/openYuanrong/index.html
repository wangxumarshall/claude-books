HUAWEI
SERVERLESS EVOLUTION

从 IaaS 到 Serverless 的演进路径

云计算经历了 IaaS (虚拟机) -> CaaS (Kubernetes 容器) -> Serverless 的发展。Serverless 的核心由两部分组成：

1. FaaS (Function as a Service)：按请求触发、毫秒级弹性计算。用户仅编写业务函数，零服务器运维。

2. BaaS (Backend as a Service)：对象存储、KV 数据库等状态托管系统。两者结合，使得开发者可以完全抛弃底层基础设施治理逻辑。

无法实现应对瞬时突发流量的“极速弹性”。

编程范式
HUAWEI
RUNTIME ABSTRACTION

无状态调用 vs 有状态 Actor

@yr.invoke (FaaS 任务)

场景：文本处理、图片压缩、推理算子
特性：每次调用都在隔离沙箱中执行，完毕后立即回收或进入休眠池。完全无状态，可支撑每秒百万级极速横向扩展。
——“用完即毁，零维护负担”

@yr.instance (Actor 模型)

场景：LLM KV Cache、游戏战斗服、长会话 Agent
特性：实例具有持久化生命周期与内存状态。客户端针对特定实例的调用，系统会自动路由至该实例所在的物理节点，实现算力与数据的亲和度调度。
——“状态就近，消除网络搬迁”

调度闭环
HUAWEI
DATA/CONTROL DECOUPLING

控制与数据解耦的调用生命周期

01
数据存入底座

用户发起 invoke(data)。庞大的 payload 直接写入 DataSystem，生成一个 ObjectRef (引用)。

02
轻量级控制流

仅将几十字节的 ObjectRef 和控制指令经 FunctionSystem 路由分发给合适的 Worker 节点。

03
计算层按需拉取

Worker 拿到引用后，向本机的 DataSystem 发起请求，通过共享内存实现数据零拷贝拉取。

04
Future 异步唤醒

计算结果写入存储池。调用方通过 Distributed Future 机制异步拉取结果，完成闭环。

HUAWEI
FUNCTION SYSTEM

多级分层调度机制剖析

Master 集群级

集群大脑。负责租户级隔离、粗粒度资源分配、全局状态监控与容错迁移。

Node Proxy

节点内守护进程。管理本节点的资源池，处理外部请求路由，并拉起 Agent 沙箱。

Agent 隔离级

沙箱进程。负责加载特定语言（Python/C++）运行时，确保多租户安全边界。

Worker 协程级

集成 Boost.Fiber。在同一沙箱内开启大量极轻量用户态线程并发处理函数，将上下文切换压至百纳秒级。

基于 CRIU 的 Snapstart 机制

为了消灭 Python 解释器启动与 AI 模型加载导致的冷启动税，元戎深度集成 CRIU (进程快照) 技术。将初始化后的黄金状态 Dump 至 NVMe 磁盘，扩容时直接从磁盘将内存镜像 Map 回进程空间，真正实现毫秒级“热重载”。

数据系统
HUAWEI
DATA SYSTEM

底层异构数据抽象 (DataSystem)

HeteroObj 异构对象

元戎的基石数据结构。无论是系统主存、SSD 磁盘，还是 NPU 的 HBM 显存，都被 DataSystem 抽象为统一的 HeteroObj 进行透明管理与引用。

KV / Object 存储池

向上暴露 Redis 风格的 KV 接口与 S3 风格的 Object 接口。用户无需额外部署第三方中间件即可完成状态读写，执行结束内存可自动垃圾回收。

Stream 流式数据

专为大语言模型 (LLM) 推理设计的长连接流式通道，支持 Token 的极速逐字回传，极大提升终端用户的首字响应时间体验。

DOWNWARD DEPENDENCY

设备与操作系统诉求

元戎的强悍性能，必须建立在先进的 Linux 内核特性与异构硬件底座之上。

KEY MESSAGE

软硬协同是突破系统性能天花板的唯一路径。

内核依赖
HUAWEI
KERNEL DEPS

对 openEuler / Linux 内核的刚性需求

POSIX 共享内存 (shm)

DataSystem 强依赖 /dev/shm (mmap)。同物理机的 Agent 与 Worker 之间传递几百 MB 的张量数据，必须通过共享内存实现 100% 零拷贝，否则序列化会导致服务瘫痪。

Namespace & cgroup v2

需要操作系统提供极轻量级的虚拟化隔离（容器化），在保证多租户安全（隔离文件/网络栈）的同时，精准限制 CPU 和内存资源的使用配额。

内核级进程快照支持

执行 Snapstart 时，需要内核暴露 ptrace 与特定的 procfs 接口供 CRIU 读取，且能够将 socket/fd 等内核态资源无损序列化并恢复。

高效线程调度模型

Boost.Fiber 的微秒级用户态协程，极其依赖宿主内核 CPU 调度的公平性与实时性，以防止阻塞操作饿死整个线程。

硬件支持
HUAWEI
HARDWARE REQ

针对异构计算的硬件设施要求

NPU / GPU 算力直通与 HBM 纳管

元戎需要直接与驱动栈交互。不仅要调度异构算力，DataSystem 还需要管理大模型加载在 GPU HBM（显存）上的 KV Cache 张量，支持显存级别的零拷贝引用。

RDMA 高速互联 (RoCEv2)

跨节点 Object 的延迟被极致压缩。传统 TCP/IP 协议栈开销过大，DataSystem 强依赖 RDMA 网卡进行内核旁路的直接显存传 (GPUDirect RDMA)，消灭网络 CPU 中断。

极速 NVMe SSD 存储池

CRIU 进程快照会在冷启动唤醒时从磁盘向内存倒灌数以 GB 计的镜像文件。底层存储设施必须配备极致性能的 NVMe I/O 池来支撑瞬时迸发的 IOPS。
