前言 / INTRODUCTION
HUAWEI
INTRODUCTION

Serverless、FaaS 与 BaaS 简述

Serverless (无服务器计算) 是一种云原生架构范式，让开发者无需管理服务器等基础设施。它由 FaaS (函数即服务) 提供按需执行的弹性计算，以及 BaaS (后端即服务) 提供对象存储、KV 存储等托管服务共同构成。

挑战与痛点
HUAWEI
CHALLENGE

传统架构与智能场景的需求差距

传统微服务和分布式编程模式中，开发者深陷于 RPC 通信、状态同步、容错重试等底层细节。随着大模型和 Agent 的爆发，AI 应用往往涉及复杂的算子调度、庞大的状态流转（如 KV Cache），现有基础设施难以支撑这种敏捷开发与极速弹性需求。

核心鸿沟

开发复杂度呈指数级上升，而云上弹性资源利用率却因为冷启动和通信开销而处于低位。

运行时抽象
HUAWEI
RUNTIME ABSTRACTION

分布式应用的三大核心抽象

Invoke (无状态)

屏蔽 RPC 细节的无状态函数调用。开发者只需定义业务逻辑，像调用本地函数一样调用远程服务，极大降低心智负担。

Instance (有状态)

面向状态的执行实体抽象。将状态与计算绑定，底层自动管理 Actor 的生命周期和容错恢复，避免数据来回搬迁。

Distributed Futures

统一的异步结果返回机制。基于 DataSystem 提供的数据对象引用 (ObjectRef)，实现跨节点的异步数据流转与按需拉取。

无状态 vs 有状态
HUAWEI
COMPARE

@yr.invoke 与 @yr.instance 的定位差异

@yr.invoke (FaaS 任务)

执行后即刻销毁或休眠，完全无状态。
适合密集型计算、临时任务、高并发无依赖逻辑。
极速扩展，零维护负担。

@yr.instance (Actor 模型)

生命周期持久化，维护内部状态。
适合数据库连接池、聊天机器人上下文、大模型 KV Cache。
状态就近处理，避免序列化开销。

调用流程
HUAWEI
WORKFLOW

函数调用的完整解耦流程

01
触发调用

用户侧触发 invoke。参数立即落入分布式数据系统 (DataSystem)。

02
控制流调度

仅传递数据引用 (ObjectRef)。调度器根据资源状态分配计算节点。

03
执行层拉取

工作节点依据引用，从共享内存或远端零拷贝拉取真实数据。

04
结果返回

结果再次存入 DataSystem，原调用方通过 Future 解析最终结果。

函数系统
HUAWEI
FUNCTION SYSTEM

多级分层调度机制

Master 集群级

负责租户管理、粗粒度资源分配与全局负载均衡。

Domain / Node

单节点或域内的守护进程，管理本机资源池与路由。

沙箱化隔离，执行具体的应用环境初始化与安全边界管理。

Worker 协程级

基于 Boost.Fiber 实现的微秒级用户态线程，极高并发执行函数。

数据系统
HUAWEI
DATA SYSTEM

数据底座架构定位

如果说 Function System 是元戎的神经网络（传递控制信号），那么 Data System 就是元戎的血液循环（传递实际状态与参数）。Data System 全权负责数据的路由、缓存、一致性及对象存储，使得函数系统彻底变为无状态枢纽。

数据接口
HUAWEI
DATA ABSTRACTION

三层数据抽象设计

HeteroObj (底层)

异构对象管理。对内存、磁盘甚至 NPU/GPU 显存进行统一抽象。支撑跨设备的异构资源纳管与调度。

KV 与 Object (中层)

核心分布式缓存与存储。同节点利用 POSIX 共享内存实现零拷贝；跨节点依赖 RDMA/TCP 进行低延迟传输。

BaaS 视图 (顶层)

对外屏蔽复杂性，为用户层代码直接暴露 Redis 风格的接口与文件系统，极大提升开发者体验。

异构硬件直通
HUAWEI
HARDWARE PASSTHROUGH

HeteroObj 与 NPU HBM 直通

1. 将大模型张量直接映射为 HeteroObj。
2. 绕过宿主内存，由 DataSystem 协调 NPU 进行 HBM 层面的零拷贝传递。
3. 面向大模型时代的极致性能优化，大幅消除 I/O 瓶颈。

KERNEL DEPS

对 openEuler 与 Linux 内核的依赖

共享内存隔离

强依赖内核稳定高效的 POSIX 共享内存机制，实现同宿主机进程间零拷贝通信。

高密沙箱隔离

依赖 namespace 和 cgroup v2 提供资源隔离机制。openEuler 的轻量化容器技术为元戎提供了优质的运行土壤。

CRIU 快照引擎

深度集成 Checkpoint/Restore in Userspace 技术。操作系统必须支持进程快照挂起与极速唤醒机制。

用户态调度

Boost.Fiber 的海量协程切换，对宿主系统 CPU 调度的公平性与实时性提出了高要求。

硬件支持
HUAWEI
HARDWARE REQ

硬件设施建设要求

AI 加速卡 (NPU/GPU)

在处理深度学习、Agent 群体智能等重负载应用时，系统向下需要硬件提供算力直通接口，DataSystem 需具备对其 HBM 的直接读写能力。

RDMA 高速网络

跨节点 Object 的延迟必须被极致压缩。传统 TCP/IP 协议栈开销过大，需要 RoCEv2 等 RDMA 技术支持内核旁路的显存直传 (GPUDirect RDMA)。

高速 NVMe SSD

进程级 Checkpoint 快照技术会在冷启动唤醒时从磁盘载入海量内存镜像，底层必须配备极致性能的 NVMe I/O 池来支撑瞬时并发 IOPS。
